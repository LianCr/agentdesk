# AgentDesk — Bilingual Insurance Agent Copilot

[![CI](https://github.com/LianCr/agentdesk/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/LianCr/agentdesk/actions/workflows/ci.yml)

Chinese-speaking insurance agents serve clients in Chinese, but their product
documents are in English. Every client question becomes a search through
dozens of PDF pages, and every answer carries the risk of saying something the
documents do not support.

AgentDesk closes that gap: **ask in Chinese, get an answer grounded in the
English source, with the page number and the verbatim quote attached** — and
when the documents do not contain the answer, it says so instead of inventing
one.

> 中文一页纸(给保险公司负责人):**[docs/one-page-zh.md](docs/one-page-zh.md)**

## Live demo

**https://agentdesk-acme307.vercel.app** — no login.

> The demo has no authentication, so anyone with the link can use the answer,
> narrative and voice endpoints, which spend OpenAI credit. They are rate
> limited per client and by a shared daily budget (see
> [Operations](#operations)). All products, carriers, rates and clients are
> **fictional**; every PDF page is stamped
> `DEMONSTRATION DOCUMENT — FICTIONAL PRODUCT — NOT FOR SALE`.

Fast path for a first look: the five sample-question chips answer instantly
(pre-verified saved answers). Typing your own question runs the live pipeline:
6 typed questions on 2026-11-17 took 28–76 s end to end, median 33 s — the UI
says so while it works.

## What it does

### 1. Grounded bilingual Q&A

Ask in Chinese; the answer is in Chinese, the evidence is the original English.
Every factual claim carries a citation card with the document, the page, and
the exact English sentence — and a link that opens the PDF at that page.

Asked for a number the documents do not contain, it refuses:

```
资料不足 Insufficient evidence · INSUFFICIENT_EVIDENCE
现有资料不足以回答这个问题的核心内容。
```

…and still cites what the documents *do* say, then lists exactly what is
missing. Asked which product is "best", a deterministic rule stops it before
the model is ever called (`FINAL_RECOMMENDATION_REQUESTED`, zero citations).

### 2. Product comparison drafts

A 13-row fact table for any two products. **The table is generated by code, not
by a model** — the model does not choose facts, assign them to products,
compare numbers, decide what is "not applicable", pick evidence, or build
citations. Every factual cell traces to a document, page and verbatim quote.

Four availability states never collapse into each other: `available`,
`not_applicable`, `not_provided`, `conflict`. A documented *"This product does
not offer optional riders"* is a **cited fact**, not a blank. If a structured
value and the document disagree, the cell shows **nothing** and reports
`conflict` — fail closed.

It never ranks the two products. There is no score, no winner, no "better fit"
field anywhere in the data structure.

### 3. Human review workflow

A draft can be sent for review. The reviewer sees a **frozen snapshot** — the
facts as they were when the review was created, hashed, and immutable at the
database level — plus four axes that are deliberately kept apart:

| | |
|---|---|
| `comparisonStatus` | are the **facts** trustworthy? *(code)* |
| `workflowDecision` | how far may this **travel**? *(code)* |
| `requiredApprovalLevel` | how much **authority** does it need? *(code)* |
| `reviewState` | how far has the **work** actually got? *(a human)* |

Collapsing these into one "high risk" badge is the mistake this design exists
to prevent. A 67-year-old client replacing an existing annuity produces
`complete` + `block_client_draft` + `licensed_agent_required` +
`pending_review`: the facts check out, it must not go to a client, a licensed
agent has to look at it, and nobody has yet.

Approve / reject / request revision each append to an **append-only** audit
trail. Two tabs racing produce one decision and one event, not two.

### 4. Post-review automation

A completed review can create a follow-up task through an n8n webhook.

There is exactly **one kind of artifact: an internal task.** The task-type enum
has no client-facing member and the payload has no recipient field — so "this
can never be emailed to a client by mistake" is not a rule someone has to
remember, it is a value the system cannot express. Rejected reviews create
nothing. With no webhook configured, the result is labelled `Demo / mock`,
never `Delivered`.

Plus **voice input**: speak a question, review the transcript, then send it
yourself. It is never auto-submitted — across repeated runs English
transcribed exactly every time and Chinese got 有现金价值 wrong once in three,
which is precisely why a human confirms before anything is asked.

## How the claims above are checked

Not by asking a model whether it did well.

| Property | How it is enforced |
|---|---|
| No fabricated citation | Every quote must be an exact substring of the retrieved chunk; page and document metadata are **injected by code**, never produced by the model |
| No unsupported claim on screen | Claims that fail validation are dropped before render, with an integrity assertion |
| No ranking / no suitability | Deterministic rules run **before** the model; no score field exists in the schema |
| Facts never invented | A structured value that disagrees with its document renders nothing (`conflict`) |
| Reviewed artifact never changes | Database triggers reject any update to the snapshot, its hash, or the routing basis |
| Audit trail never rewritten | Append-only triggers refuse UPDATE entirely and DELETE except for test-prefixed rows |
| One decision, one event | Advisory lock + compare-and-set inside one transaction; a stale second writer gets a conflict and changes nothing |
| Automation can't reach a client | No client-facing task type and no recipient field exist |

Frozen evaluations, all deterministic and model-free where it matters:

- **[M3](docs/m3-evaluation.md)** — 30 frozen questions + 21 red-team probes.
  Deterministic invariants (unsourced facts on screen, wrong citation page,
  invalid quote) were **zero in every observed run**; the model-dependent
  quality metrics are reported as a distribution, not a single lucky number.
  The last recorded run scored 28/30 cases and 13/18 probes.
- **[M4](docs/m4-evaluation.md)** — 23 frozen comparison cases,
  **17/17 deterministic hard gates pass**, 16 mutation tests proving the
  evaluator can fail.
- **[M5](docs/m5-evaluation.md)** — 41 frozen workflow cases,
  **19/19 hard gates at zero**, 21 mutation tests. No model is involved in this
  evaluation at all.
- **[M6](docs/demo-acceptance.md)** — 10 end-to-end demo scenarios run in a
  browser, which found two defects no suite had.

Test suites: **441 unit · 81 database · 104 browser**. Knowledge base is frozen
at 3 documents / 20 pages / 45 chunks and verified unchanged by every run.

### CI & evals

Every push and pull request runs [`.github/workflows/ci.yml`](.github/workflows/ci.yml)
— two blocking jobs, no secrets, no paid API calls:

| Job | What runs | Fails the build when |
|---|---|---|
| `checks` | data / chunk / PDF validators, `tsc`, **441 offline unit tests**, `next build` | any validator, type error, test or build fails |
| `db-evals` | ephemeral Supabase (Postgres 17 + pgvector) started in the runner from `supabase/migrations`, then **81 database tests**, the **M4** comparison eval (23 frozen cases) and the **M5** workflow eval (41 frozen cases) | any test fails; any of M4's 17 hard gates fails; any of M5's 19 hard gates is non-zero, any M5 case fails, or test rows are left behind |

The eval reports are uploaded as a build artifact (`eval-reports`).

What CI does **not** prove, stated plainly:

- **M3 is not in CI.** It calls OpenAI for every question, and its free-text
  detectors have known false positives (M3.1 in `docs/backlog.md`). It is run
  by hand.
- **The CI knowledge base has placeholder vectors.** The three documents are
  seeded from the committed derived pages and chunks, so the database is the
  same 3/20/45 the evals check stays unchanged — but the embeddings are
  deterministic placeholders (`embedding_provider = 'ci-placeholder'`,
  [`scripts/ci-seed-knowledge-base.ts`](scripts/ci-seed-knowledge-base.ts),
  which refuses any non-localhost database). Nothing in CI measures retrieval
  quality; M4 and M5 do not use retrieval.
- Live/smoke tests (real API calls) and the 104 browser tests are not in CI.

## Integrations & API

### What AgentDesk calls

| Dependency | Used for | If it is down or not configured |
|---|---|---|
| **OpenAI** — `text-embedding-3-large`, `gpt-5-mini`, `gpt-4o-mini-transcribe` | query embeddings, Chinese query rewrite, answer draft, comparison narrative, voice transcription | typed questions return a 500 / `UPSTREAM_BUSY`; the narrative degrades to `unavailable` (the table stays); comparison and reviews are unaffected (no model) |
| **Supabase Postgres + pgvector** (secret key, server only) | knowledge base, `match_chunks` vector search, reviews + audit events, automation runs, rate-limit counters | `/api/health` → `down` (503); see [RUNBOOK §1](docs/RUNBOOK.md) |
| **n8n webhook** (optional, `N8N_WEBHOOK_URL`) | create an internal follow-up / revision task after a review | runs are recorded as `mocked` and the UI says nothing was sent |

The n8n contract is small and fixed: the server builds the payload from the
stored review (schema-versioned, no recipient field, task type is
`internal_followup` or `internal_revision`), sends an optional shared-secret
header, waits at most 10 s, and requires an acknowledgement body. Each run is
a row in `automation_runs` moving `pending → delivered | failed | mocked`; the
unique idempotency key `reviewId:terminalEventId` means a retry or a second tab
can never create a second task. Workflow export: [`n8n/`](n8n/).

### What AgentDesk exposes

Full contract: **[`public/openapi.json`](public/openapi.json)** (OpenAPI 3.1,
served at `/openapi.json`; a test fails if it drifts from `app/api`). No
authentication — it is a public demo. Every response carries `x-request-id`.

| Method | Path | What it does | Model? | Rate limited |
|---|---|---|---|---|
| GET | `/api/health` | config presence, DB round trip, frozen 3/20/45 check | no | no |
| POST | `/api/answer` | grounded bilingual answer with page citations, or a refusal | yes | 10 / 10 min / IP |
| POST | `/api/compare` | deterministic 13-row comparison draft | no | no |
| POST | `/api/compare/narrative` | optional neutral narrative for that draft | yes | 10 / 10 min / IP |
| GET | `/api/reviews?state=` | review queue | no | no |
| POST | `/api/reviews` | send a comparison for review (idempotent) | no | no |
| GET | `/api/reviews/{id}` | one review with its audit trail | no | no |
| POST | `/api/reviews/{id}/decision` | approve / reject / request revision (409 if stale) | no | no |
| GET | `/api/reviews/{id}/automation` | what the automation *would* send; past runs | no | no |
| POST | `/api/reviews/{id}/automation` | create the internal task (n8n or mock) | no | no |
| POST | `/api/transcribe` | speech → editable text (multipart `audio`) | yes | 20 / 10 min / IP |

The three model routes also share one budget of 300 calls per UTC day.

### MCP server (read-only)

`mcp/server.ts` exposes the frozen knowledge base and the code-only comparison
engine to MCP clients such as Claude Code or Claude Desktop, over stdio. It
reads the committed files only: **no database, no API key, no network call**,
so it cannot spend credit, write a review or trigger automation. All four tools
are annotated `readOnlyHint`.

| Tool | Returns |
|---|---|
| `list_documents` | the 3 fictional product guides with page and chunk counts |
| `search_knowledge_base` | BM25 keyword hits over the 45 chunks — verbatim excerpt, document, page, PDF link |
| `get_chunk` | one chunk's full verbatim text and page range, for checking a quote |
| `compare_products` | the same 13-row cited comparison draft the web app builds |

```bash
claude mcp add agentdesk -- npm --prefix /path/to/agentdesk run --silent mcp
```

Claude Desktop (`claude_desktop_config.json`):

```json
{ "mcpServers": { "agentdesk": { "command": "npm", "args": ["--prefix", "/path/to/agentdesk", "run", "--silent", "mcp"] } } }
```

Honest limits: search is **lexical**, not the web app's pgvector retrieval;
Chinese questions only match through the fixed insurance glossary (e.g.
现金价值 → cash value), so phrasing outside it (提前取款) finds little — ask in
English or use the web app. The grounded-answer pipeline is not exposed: it
needs OpenAI and pgvector, and its citation checks live server-side.
Contract tests: `tests/mcp/server.test.ts` (a real MCP client over an in-memory
transport).

## Operations

**Health.** `GET /api/health` — measured against the live database on
2026-11-17, before the rate-limit migration was pushed (hence `degraded`):

```json
{
  "status": "degraded",
  "config": { "supabaseUrl": true, "supabaseSecretKey": true, "openaiApiKey": true, "n8nWebhook": false },
  "database": { "reachable": true, "latencyMs": 848, "errorCode": null },
  "knowledgeBase": { "expected": { "documents": 3, "document_pages": 20, "chunks": 45 },
                     "actual":   { "documents": 3, "document_pages": 20, "chunks": 45 }, "frozen": true },
  "rateLimiter": { "tableReachable": false },
  …
}
```

`ok` → everything present; `degraded` (200) → serving, but the knowledge base
drifted, the limiter table is missing or there is no OpenAI key; `down` (503)
→ database unreachable. It never calls OpenAI.

**Logs.** One JSON line per API request, written to stdout (Vercel keeps it
per invocation). Real lines from a local run:

```json
{"ts":"2026-11-18T01:13:23.965Z","level":"info","event":"request","requestId":"demo-req-1","route":"/api/compare","method":"POST","status":200,"durationMs":11}
{"ts":"2026-11-18T01:13:24.004Z","level":"warn","event":"request","requestId":"4490913f-…","route":"/api/answer","method":"POST","status":400,"durationMs":1}
```

Answer requests add `queryLength`, `evidenceStatus`, `citationCount`; blocked
requests add `rateLimit` and `rateLimitRule`. Question text, audio, IP
addresses and error messages are never logged.

**Rate limits.** Fixed windows counted in Postgres by one atomic RPC
(`rate_limit_hit`: `insert … on conflict do update … returning`) — serverless
instances share no memory, so an in-process counter would not work. Keys are
an HMAC of rule + IP, never the raw IP. If the counter store is unavailable
the request is allowed and the log line says `"rateLimit":"unavailable"`; the
OpenAI spend cap stays the hard backstop.

## What it deliberately does not do

- **No final recommendation, no suitability determination.** Not a limitation
  to fix later — it is the product boundary.
- **No authentication.** `"Demo Reviewer"` is a server-owned placeholder, not
  an identity claim.
- **No client communication capability at all.** Not disabled — absent.
- **Fictional data only.** No real carrier, product, client or PII.
- **Demo rules are not legal conclusions.** The age-65 threshold and
  replacement-review rules are this project's business policy for fictional
  products, and would need compliance and licensed-agent sign-off in reality.
- **No compliance certification is claimed.**

Gaps between this demo and a production system are enumerated in
**[docs/demo-to-production.md](docs/demo-to-production.md)** — including the
ones that are inconvenient.

## Architecture

```text
English product PDFs (generated from one source of truth)
   │  heading/table-aware chunking, page metadata
   ▼
Supabase Postgres + pgvector ── RLS on, zero policies, no client access
   │
   ├─► Q&A:        zh query ─► multi-route retrieval ─► strict-schema draft
   │                          ─► code verifies every quote ─► grounded answer
   │
   ├─► Compare:    products.json ─► fact registry ─► 13-row table (no model)
   │                          ─► optional neutral narrative, guard-checked
   │
   ├─► Review:     server rebuilds draft ─► frozen snapshot + sha256
   │                          ─► human decision ─► append-only audit
   │
   └─► Automation: terminal review ─► internal task ─► n8n webhook / mock
```

Next.js App Router · TypeScript · Supabase Postgres + pgvector · Vercel AI SDK ·
zod at every boundary · OpenAI `text-embedding-3-large` + `gpt-5-mini` +
`gpt-4o-mini-transcribe` · n8n via a controlled webhook · Playwright.

Model choices and their measured trade-offs: **[docs/model-selection.md](docs/model-selection.md)**.
One-page architecture with a diagram: **[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)**.

## Run it locally

```bash
npm install && npx playwright install chromium
cp .env.example .env          # OPENAI_API_KEY, SUPABASE_URL, SUPABASE_SECRET_KEY
npm run db:push               # apply migrations
npm run ingest:products -- --embedding=openai
npm run dev                   # http://localhost:3000
```

Useful commands:

```bash
npm run validate:data          # products, cases, manifests against their schemas
npm run validate:ingestion     # database vs committed fixtures (read-only)
npm run ask -- "定期寿险有现金价值吗？"        # grounded answer from the CLI
npm run compare -- --a=doc_securerate5_v1 --b=doc_indexflex_ul_v1
npm run review -- --a=doc_securerate5_v1 --b=doc_indexflex_ul_v1 --case=DEMO-2026-003
npm run eval / eval:comparison / eval:workflow   # the frozen evaluations
npm test / test:db / test:ui
```

Deployment and environment variables: **[docs/deployment.md](docs/deployment.md)**.

One source of truth: `data/fictional-products/products.json`. The PDFs, the
manifest, the comparison cells and the evaluation ground truth are all derived
from it — the same number is never maintained by hand in two places.

## Disclaimer

本演示使用虚构保险产品与合成场景。AI 生成内容仅用于内部比较与知识辅助,不构成
报价、保单演示、适合性判断、法律或税务意见,也不构成最终保险推荐。标注处需持牌
保险经纪人审核。

Demo uses fictional insurance products and synthetic scenarios. AI-generated
content is for internal comparison and knowledge assistance only. It is not a
quote, policy illustration, suitability determination, legal or tax advice, or
final insurance recommendation. Licensed-agent review is required where
indicated.
