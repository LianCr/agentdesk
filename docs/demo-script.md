# AgentDesk 4 分钟演示脚本 / Live Demo Script (~4:00)

**对象**：非技术背景、以中文为主的保险公司负责人。
**环境**：`npm run dev` → 浏览器打开 `http://localhost:3000`。
**基调**：平实、自信、不夸张。全程可自然强调一句话——**演示数据全部为虚构产品**（每页 PDF 都印有 DEMONSTRATION DOCUMENT — FICTIONAL PRODUCT — NOT FOR SALE）。

## 开场前检查清单

- [ ] `npm run dev` 已启动，`http://localhost:3000` 正常打开，页面标题显示 **AgentDesk**
- [ ] 五个预设问题各点过一次预热（首次回答约 15–40 秒，预热后更稳）
- [ ] 浏览器允许新标签页打开 PDF（点一次「打开原文第 N 页」确认能跳到指定页）
- [ ] 关掉无关标签页与通知；字体缩放调到观众能看清引用卡片的程度

**风险与备用方案**：若现场回答偏慢，就顺着屏幕上的三行加载状态讲解——「检索保险资料中 → 生成有据草稿中 → 校验引用中」，这三步是真实流水线阶段，不是动画；若某题返回「部分证据」，就照实讲证据徽章的含义：系统只承认它能证明的部分，这正是卖点。

---

## 1. 业务问题（0:00–0:20）

**演示操作**：停在首页，不点击。指一下副标题「中文提问，检索英文保险资料，并返回可验证的原文引用与页码」。

**讲词**：
> 「您的经纪人服务中文客户，但产品资料全是英文 PDF。客户问一句，经纪人要翻几十页，还要保证不说错。AgentDesk 解决的就是这个信任缺口：中文提问，答案来自英文原文，每句话带页码引用。今天所有产品数据都是虚构的演示资料。」

## 2. 中文提问 → 英文原文引用（0:20–1:05）

**演示操作**：点预设问题「**定期寿险有现金价值吗？**」。等待时指三行加载状态念一遍。答案出现后，指绿色徽章「证据充分 Strong evidence」，再滚动到引用卡片，点「**打开原文第 2 页**」，新标签页打开 PDF 第 2 页。

**讲词**：
> 「用户中文问：定期寿险有现金价值吗。回答是中文的，但请看下面的引用卡片：Demo TermPlus 20 Product Guide，第 2 页，英文原文——"Cash Value None. The policy does not accumulate cash value." 点一下，PDF 直接跳到第 2 页，经纪人可以当着客户的面核对原文。回答里每个上标数字都对应这样一张卡片。」

## 3. 数字事实与精确页码（1:05–1:50）

**演示操作**：点预设「**IUL 的 current cap 和 guaranteed minimum cap 是多少？**」。答案出现后指出两个数字（current cap 9.50%，guaranteed minimum cap 3.00%），再指引用卡片（Demo IndexFlex UL，第 5 页），最后指「证据摘要」区块：引用来源、已验证事实、引用覆盖率、需要人工审核。

**讲词**：
> 「数字是保险问答里最容易出错的地方。这里 current cap 9.50%、保证最低 3.00%，两个数字都锁定到 IndexFlex UL 文档第 5 页的原文。下面这个证据摘要不是模型自己打分——检索了几份来源、几条事实通过了引用校验、覆盖率多少，全是代码算出来的事实指标。」

## 4. 资料缺失时的安全行为（1:50–2:35）★ 本场重点

**演示操作**：点预设「**TermPlus 61 岁续保费是多少？**」。答案出现后指灰色徽章「**资料不足 Insufficient evidence**」、「资料中没有提供」清单、「建议下一步」以及黄色横幅「**需要持牌保险经纪人审核**」。

**讲词**：
> 「这题是我们故意设的陷阱：文档里的费率表只到 60 岁投保，61 岁的续保费根本不在资料里。一般的 AI 会编一个数字给您。AgentDesk 的回答是：它引用已知事实——续保按 attained-age 逐年调整、以保单 schedule 为准——然后明确列出缺什么，建议查保单 schedule 或联系 carrier，并挂上持牌经纪人审核的横幅。**它拒绝编造**。对保险业务来说，这比答得快重要得多。」

## 5. 红线：不做最终推荐（2:35–3:10）

**演示操作**：在输入框手动输入「**Which product is best?**」并提交。答案出现后指审核横幅和「最终推荐请求 Final recommendation requested」标签，指出引用区为空。

**讲词**：
> 「如果有人直接问哪个产品最好——这是合规红线。这类问题在到达模型之前就被代码规则拦下：系统只提供有据可查的事实和差异，不做最终推荐、不做 suitability 判断，这些永远留给持牌经纪人。注意这条规则是写在代码里的，模型再聪明也绕不过去。」

## 6. 一句话技术可信度（3:10–3:40）

**演示操作**：回到主页面，不展示代码。

**讲词**：
> 「背后简单说三句：三份英文产品 PDF 按页切分存入向量数据库，中文问题走中英双路检索保证查得全；模型只能引用真正检索到的证据，每条英文引文都由代码逐字核对确属原文；页码和引用是程序注入的，任何没有出处的说法根本不会显示在屏幕上。我们在冻结的演示评估集上反复运行验证——在观察到的每一轮运行中，屏幕上的无出处事实和引用页码错误都是零，因为这几条是代码强制的，不依赖模型发挥。AI 本身有随机性，我们不宣称它永远 100% 正确，但这些确定性的底线是每一轮都成立的。」

## 7. 人审边界与下一步（3:40–4:00）

**演示操作**：指页面底部的中英双语免责声明。

**讲词**：
> 「所有面向客户的内容都要经过持牌经纪人审核，屏幕上的横幅就是这条边界。下一阶段是产品比较草稿和人工审核工作流：逐格可追溯引用的比较表、缺失信息清单、审批流转。今天看到的引用与拒答机制，就是那一切的地基。」

---

**一句话总结**：AgentDesk 让中文经纪人用客户的语言回答问题，每个事实带英文原文页码引用，查不到就明说查不到——**可验证，不编造，最终判断永远留给持牌的人**。
